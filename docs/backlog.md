### 背景

安装版用户目前升级需要手动下载新的 `Less Todo Setup x.y.z.exe` 并覆盖安装。
README 的"已知限制"也写明了"无自动更新，升级需重新安装"。

### 目标

应用能自己发现新版本、下载并安装更新，用户不需要手动重新下载安装包。

### 期望行为（初步，待设计细化）

- 启动后静默检查 GitHub Releases 是否有更高版本，不打扰用户。
- 有新版本时在窗口内或托盘轻提示，不弹模态框、不抢焦点，保持既有交互原则。
- 用户确认后下载并安装；可支持"退出时安装"，避免打断正在做的事。
- 无新版本、离线或请求失败时静默忽略，不影响应用正常使用。
- 设置里能看到当前版本号，并提供手动"检查更新"。
- 更新过程不改动或清空本地数据（`%APPDATA%\less-todo-window\`）。

### 技术方向（设计时确认，不是结论）

- 已有的 electron-builder + NSIS 配置可继续使用，评估 `electron-updater` +
  GitHub Releases provider 的组合。
- 发布产物需要包含更新元数据（如 `latest.yml`），`build:win` 与发布流程要相应调整。
- 需要确认安装包是否签名，以及未签名更新在 Windows SmartScreen 下的表现。
- 更新检查走主进程，渲染层只负责展示状态，保持现有进程职责划分。

### 验收标准（初稿）

- 旧版本安装版能检测到更高版本并完成升级，升级后任务数据与设置不丢。
- 没有新版本、断网或接口失败时不出现可见报错，应用照常可用。
- README 的功能列表与"已知限制"同步更新。

### 待定问题

- 更新提示的形态与频率：每次启动都提示，还是每个版本只提示一次？
- 是否支持跳过某个版本？
- 是否需要 beta / 预发布渠道，还是只跟正式 Release？
